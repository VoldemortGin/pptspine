# Changelog

All notable changes to **pptspine** are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

pptspine is an Apache-2.0-licensed, pure-Rust PowerPoint (`.pptx`) reader with
PyO3 Python bindings and a fidelity-preserving **PDF export** built on the
shared `pdf-typeset` engine from [pdfspine](https://pypi.org/project/pdfspine/).
It is **alpha / pre-1.0**: the core is feature-complete, but the public API may
still change.

## [Unreleased]

### Added

- Python: `pptspine.open(path, ...)` and `pptspine.open_bytes(data, ...)` take optional keyword-only zip limits — `max_entries`, `max_entry_bytes`, `max_total_bytes`, `max_compression_ratio`, `max_name_len`, `max_slides` — so callers can tighten them for untrusted input or relax them for very large legitimate decks, plus four expansion budgets (`max_diagram_shapes`, `max_diagram_text_bytes`, `max_chart_points`, `max_comments`; see Security). Omitted / `None` keeps the defaults exactly; zero, negative, non-integer or `bool` values raise `ValueError`; exceeding a zip limit raises `PptZipError` as before (an expansion budget never raises: it degrades and records a diagnostic). No existing call changes behavior.
- Image-table geometry reconstruction. `ppt_ocr::reconstruct_table_from_image` (previously a stub that always returned `Unsupported`) now OCRs an image and rebuilds a row / column grid from the word boxes (`ImageTable` / `ImageTableCell` / `ImageTableOptions` / `ImageTableResult`; pure-geometry kernel `reconstruct_from_words` is separately callable and unit-tested with synthetic boxes). Ported from docspine `doc-ocr/src/table.rs` (commit `8e64134`; itself from pdfspine) — the third same-origin copy in the family, so it is due for evaluation as an ocrspine promotion (noted in the module header only). Python: `pptspine.reconstruct_image_table(data: bytes) -> list[dict]` with the same name and shape as docspine (`bbox` / `row_count` / `col_count` / `cols` / `rows` / `cells`). Breaking for Rust callers: the stub's signature changed from `(bytes) -> Result<()>` to `(bytes, &ImageTableOptions) -> Result<ImageTableResult>`.
- `a:custGeom` is now evaluated and drawn as its real outline instead of a bounding-box rectangle. New `ppt_core::custgeom` model (`CustGeom` / `Guide` / `CustPath` / `PathCmd`, carried on `AutoShape` / `Connector` `.cust_geom` and the resolved IR) parsed from `a:avLst` / `a:gdLst` / `a:pathLst > a:path` (`w` / `h` / `fill` / `stroke` / `extrusionOk`; `moveTo` / `lnTo` / `cubicBezTo` / `quadBezTo` / `arcTo` / `close`). `ppt-render::custgeom` evaluates the guide formulas (`val` `*/` `+-` `+/` `?:` `abs` `at2` `cat2` `cos` `sin` `tan` `sat2` `max` `min` `mod` `pin` `sqrt`; built-ins `w h l t r b hc vc wd2..wd32 hd2..hd10 ss ls ssd2..ssd32` and the angle constants `cd2 cd4 cd8 3cd4 3cd8 5cd8 7cd8`, angles in 1/60000 degree) in declaration order (later guides shadow earlier ones and built-ins; forward / self references are undefined), scales path coordinates from the path's `w` x `h` (shape size when absent) to the frame, turns `quadBezTo` into cubics and `arcTo` into at most 90-degree cubic segments from the current point (visual angles, ellipse-correct). Each `a:path` is painted by its own `fill` / `stroke` (`none` strokes only; `lighten` / `darken` variants paint as `norm`, no warning); a picture fill clips to the real outline; open paths keep line-end decorations. Budgets against hostile input: 1024 guides, 256 paths, 20 000 path commands. Over budget (a new parse diagnostic `custom-geometry-degraded`, `{part, count}`) or a failed evaluation (undefined name, division by zero, NaN / infinity) falls back to the old bounding box + `custom-geometry-approximated` warning. `DiagnosticKind::CustomGeometryDegraded` is new. Breaking for Rust callers: `AutoShape` / `Connector` / `ResolvedAutoShape` / `ResolvedConnector` gain a `cust_geom` field (struct literals need it; `custom_geometry: bool` is unchanged).
- `to_text` / `to_markdown` / `Slide.text` print the evaluated slide number for `a:fld type="slidenum"` fields (Markdown title lines included), so text exports agree with the PDF instead of echoing the cached `‹#›` / stale number. The evaluation stays in one place (`resolve.rs`): the exporters take a field run's text from the resolved run paired with it (`datetime*` fields keep their cached text there; without a resolved IR — `slide_text` / `presentation_text` / `*_with(.., None, ..)` — the cached text is used as before). Table cells are not paired with resolved runs, so a field inside a cell still prints its cached text.
- PDF export: an OLE object without a preview image (placeholder box only) now emits an `ole-degraded` warning, matching `smartart-degraded` / `chart-degraded` and `docs/PRD-PDF-EXPORT.md` ("placeholder box + warning"); previously nothing was reported.
- Fuzz coverage: new `parse_parts` target (first byte picks layout / master / theme / chart / tableStyles / notes / comments / SmartArt drawing / SmartArt data / presentation, the rest is that part's XML, every other part minimal-valid and referenced from the slide), every parsing target now also runs the `to_text` / `to_markdown` exporters (both orders, hidden slides, with and without the resolved IR) and the render mapping (`resolve`), seeds for the new target in `make_seeds`, a row in the `fuzz.yml` matrix. Minimal triggers of the problems fixed in this series (expanded-form `a:off`, repeated slide references, `mc:AlternateContent` without Fallback, deeply nested formulas / groups) are pinned as ordinary `cargo test` regressions in `crates/ppt-parse/tests/fuzz_regressions.rs`. No code under `crates/` changed for this item.
- Parse diagnostics channel: `Presentation.diagnostics` (Python `Presentation.diagnostics()` → `list[dict]`, stub updated) lists content that was silently lost or degraded while parsing, so callers (e.g. a RAG pipeline) can tell a result is incomplete. Each entry carries only a kind (`#[non_exhaustive] DiagnosticKind`, stable kebab-case `code()`), the part path and a count — never document text; a clean file yields an empty list. Kinds: `xml-truncated` (a part's XML broke mid-way or ended with open tags — the parsed prefix is still returned; count = byte offset where parsing stopped), `nesting-too-deep` (subtrees skipped past the 64-level group / `mc:AlternateContent` limit; count = subtrees), `duplicate-slide-ref` (repeated `p:sldId` references to one slide part, deduplicated; count = dropped references), `missing-part` (relationships pointing at parts absent from the package, per source part; external links excluded), `smartart-degraded` (no usable drawing part: placeholder box + data text only) and `chart-degraded` (chart part present but malformed / without series). Collection is centralized in `zip_pkg::Package` (the single `part_str` read entry does one well-formedness scan per part, `.rels` reads check dangling targets, `Package::note` merges counts per `(kind, part)`); the per-walker `Err(_) => break` code is unchanged. `Presentation` gains the `diagnostics` field (Rust struct literals need it).
- Shape picture / pattern fills. `a:blipFill` on a shape's `spPr` (round avatars, picture-filled rounded rectangles) is now parsed into `Fill::Blip(BlipFill { rel_id, media_name, src_rect, fill_rect, tile })` and drawn in the PDF: the image is placed with the same `fillRect` / `srcRect` logic and the same embed cache as `p:pic` (one image used by a shape fill and a picture is embedded once) and **clipped to the shape's own geometry outline** (pdf-typeset `Op::Group.clip` takes an arbitrary path, so ellipses etc. clip exactly; a degraded preset / `custGeom` clips to the bounding box with the usual warning). `a:tile` is drawn stretched with a `blip-fill-tiled` warning. `a:pattFill` (`Fill::Pattern { fg, bg }`) used to become no fill; it now degrades to a flat color — the mean of `a:fgClr` and `a:bgClr` (missing fg = black, bg = white) — with a `pattern-fill-degraded` warning. `a:grpFill` (`Fill::Group`) inherits the fill of the nearest enclosing group that has a real fill (a group that is itself `grpFill` / unset defers upward; no group fill = no fill); `GroupShape.fill` carries `p:grpSpPr`'s own fill. `ResolvedFill::Pattern` and `ResolvedAutoShape.blip_fill` are new in the resolved IR. Python shape dict `fill`: pattern fills report the foreground (else background) color; picture / `grpFill` stay `None`.

- PDF export evaluates `a:fld type="slidenum"` fields to the slide's displayed page number = slide index in presentation order + `p:presentation@firstSlideNum` (default 1; new `Presentation.first_slide_num`) − 1. Hidden slides still occupy a number (PowerPoint behavior), so exporting without them does not renumber the rest. Applies to any text carrying the field (slide `sldNum` placeholders, ordinary text boxes, inherited master / layout shapes). Other fields such as `datetime*` keep the text cached in the file — the system clock is never read, so output stays deterministic. `sldNum` / `ftr` / `dt` placeholders that exist on a slide were already drawn through the placeholder chain (layout → master geometry and style, text from the slide itself); template placeholders on layout / master are still never drawn unless the slide instantiates them. `to_text` / `to_markdown` now evaluate `slidenum` the same way (see below).
- OLE object previews: the `p:pic` inside `p:oleObj` (Excel sheets, Visio drawings, …) now enters the model as a picture positioned by the frame's `xfrm` and is drawn like any picture in the PDF, instead of the whole OLE frame being a bare placeholder. Works for `p:oleObj` directly under `graphicData`, for `mc:AlternateContent` inside `graphicData`, and for `mc:AlternateContent` wrapping the whole `graphicFrame` (PowerPoint 2010+: the Choice holds only `p:embed`, the Fallback the preview). To make that last case work, an `mc:AlternateContent` branch whose only content is an OLE placeholder with no preview counts as weak: a branch with real content wins, otherwise the first non-empty branch is kept (all previous Choice / Fallback outcomes are unchanged). EMF / WMF previews degrade through the existing unsupported-image path (`ImageDropped` warning, nothing drawn); no preview keeps the placeholder box. `progId` is not recorded (no suitable model field).
- Slide comments: legacy `ppt/comments/commentN.xml` (`p:cmLst > p:cm`, author via `authorId` → `ppt/commentAuthors.xml`, `dt`, `p:pos`, `p:text`) and modern threaded comments (`p188:cmLst`, author GUID → `ppt/authors.xml`, `created`, `p188:txBody`, `p188:replyLst` replies) are parsed through the slide's rels into `Slide.comments` (`Comment { author, initials, datetime, text, position, replies }`, missing attributes → `None`) and exposed as Python `Slide.comments()` (stub updated). Comments are review metadata: they are not part of `to_text` / `to_markdown` / `Slide.text` and are not drawn in the PDF; author names and bodies are never written to warnings.
- SmartArt text: `graphicFrame` > `dgm:relIds` is no longer dropped. The pre-rendered drawing part (`ppt/diagrams/drawingN.xml`, located via `dsp:dataModelExt@relId` in the data part, else the slide's `diagramDrawing` rel with the matching number) is parsed by the regular shape parser (`dsp:sp` is isomorphic to `p:sp`) and enters the model as a group whose rect is the frame and whose child space is `(0,0,frame.ext)`, so text export and PDF rendering just work. A drawing that is missing, not well-formed or empty falls back to the data part: content points (`dgm:pt > dgm:t`, document order; `pres` / `parTrans` / `sibTrans` skipped) become `GraphicPlaceholder.diagram_text` (Python placeholder dict key `text`) and flow into `to_text` / `to_markdown`; the PDF keeps the placeholder box and now emits a `smartart-degraded` warning for any SmartArt placeholder. A drawing / data part shared by several frames is parsed once (each frame still gets its own copy of the shapes; total expansion is capped by the budgets under Security). `dsp:txXfrm` (text rectangle) is not used; text lays out in the shape bounds.
- Semantic extraction: visual reading order for `to_text`/`to_markdown`/`Slide.text` (XY-cut over flattened group geometry; `order="document"` restores z-order); Markdown titles from `title`/`ctrTitle` placeholders, `- `/`1. ` list markers from the resolved bullet chain, `![alt](media)` images (`cNvPr@descr`, falls back to `@name`), `[text](url)` external hyperlinks; `shapes()` dicts gain `placeholder`, `hyperlink`, `alt_text`/`title`/`name`; run dicts gain `hyperlink`; `Slide.hidden`, `Presentation.sections()`, `Presentation.core_properties()`.
- PDF export draws slideMaster / slideLayout non-placeholder shapes (logos, decorative bars, footer rules, fixed footer text) beneath slide content, honoring `showMasterSp` on slides (hides master + layout graphics) and layouts (hides master graphics). Master/layout pictures and picture backgrounds now resolve through their own part rels (previously dropped silently). `Slide.shapes()`, `to_text()` and `to_markdown()` remain slide-only.
- Run-level `a:rPr@spc` (signed character spacing), `@baseline` (superscript/subscript using the document's own offset; glyph ×0.65) and `@cap` are parsed, inherited through `txStyles`/`lstStyle`, exposed in the run dict (`char_spacing_pt` / `baseline` / `cap`) and rendered via pdf-typeset `CharacterSpacing` / `ResolvedScriptPlacement`. Over-condensed paragraphs fall back with a `SignedSpacingFallback` warning; `cap=small` is approximated as all caps with a one-time `small-caps` warning. Default decks render byte-identical PDFs.
- PDF export draws line ends `a:headEnd` / `a:tailEnd` (triangle / stealth / diamond / oval / arrow; sm/med/lg sized per LibreOffice ratios) on open outlines, shortening the stroke to the arrow base; inherited via `lnRef` → theme `lnStyleLst`. Unsupported kinds degrade with a `line-end-degraded` warning.
- Chart data extraction: `graphicFrame` charts now read `ppt/charts/chartN.xml` cached data (`strCache`/`numCache`/literals; no external workbook) — kind, title, categories, series name/values/`formatCode`; sparse `pt` padded to `ptCount`; missing caches yield empty series + `warnings`. Exposed as the `chart` key on placeholder shape dicts, `#### Chart: <title>` + table in `to_markdown()`, and `category: v, v` lines in `to_text()`. PDF rendering unchanged (placeholder box).
- Table styles: `ppt/tableStyles.xml` is parsed (`wholeTbl` / `band1H` / `band2H` / `band1V` / `band2V` / `firstRow` / `lastRow` / `firstCol` / `lastCol`: `tcStyle` solid fill + `tcBdr` borders incl. `insideH`/`insideV`, `tcTxStyle` color + bold) together with the `a:tblPr` flags (`firstRow`/`lastRow`/`firstCol`/`lastCol`/`bandRow`/`bandCol`), and resolved per cell in OOXML precedence (header / total rows excluded from band counting); explicit `tcPr` fill / borders (now incl. `a:noFill`) and run properties still win. PDF export draws the effective fills, borders and text color/bold. The `table-style` warning now fires only when the `tableStyleId` is not found (or `tableStyles.xml` is missing / malformed). Unsupported style items (corner cells, `tblBg`, gradient fills, `fillRef`/`lnRef`, diagonals) are skipped. Tables without a `tableStyleId` render unchanged.
- PDF export renders charts as vector graphics instead of the placeholder box: bar/column (clustered, stacked, percentStacked; `c:barDir`), line (gaps break the line, point markers) and pie (wedges as Bézier arcs) from the cached chart data, with a nice value axis (0 baseline, negatives, all-zero / NaN / huge values safe), thinned category labels, gridlines, title, legend and series colors cycling the slide theme's accent1..6 (`ResolvedSlide.accents`; Office palette without a theme). Other kinds (area, scatter, radar, doughnut, …), 3D and combo charts, missing chart parts / data, more than 20 000 points or tiny frames keep the placeholder box and now emit a `chart-degraded` warning. The chart model gains `bar_dir` / `grouping` / `three_d` / `combo` (also in the Python chart dict). Geometry lives in the pure `ppt-render/src/chart.rs` layout functions.
- Charts use the colors stored in the file and draw data labels: `c:ser/c:spPr` solid fill (line series: `a:ln` color) and per-point `c:dPt` colors (scheme colors + transforms resolved through the theme; gradient/pattern fills fall back to the accent cycle), and `c:dLbls` `showVal` / `showCatName` / `showPercent` (series level overrides chart-type level) drawn at column/bar ends, above line points, centered in stacked segments and inside pie wedges. Labels are thinned deterministically (a label overlapping an already kept one, or not fitting inside its wedge / segment, is dropped); percentages use largest-remainder rounding so they sum to 100. `c:numFmt` format codes are not read (default number format). `ofPieChart` (compound pie) no longer renders as a plain pie: it keeps the placeholder box + `chart-degraded` (`Chart.of_pie`). Model: `ChartSeries.color` / `point_colors` / `labels`, `Chart.of_pie`; Python series dicts gain `color` / `point_colors` / `labels`, chart dicts `of_pie`.
- PDF export writes run-level external hyperlinks (`a:hlinkClick` with a rels URL) as `/Link` URI annotations (pdf-typeset `RunStyle.link`; one rectangle per laid-out line). Only `http` / `https` / `mailto` targets are emitted; `javascript:`, `file:` and other schemes are dropped. Internal slide jumps and shape/picture-level links still produce no annotation. `ResolvedRun.link` carries the raw target.
- Formulas: `a14:m` OMML (`m:oMathPara` / `m:oMath`) in a paragraph is extracted as a `RunKind::Math` run (run dict `kind == "math"`) holding linearized text — `m:f` → `a/b` (operands with several fragments or compound structure are parenthesized: `(a+b)/c`), `m:sSup` → `x^2`, `m:sSub` → `x_i`, `m:rad` → `sqrt(x)` / `root(3,x)`, other structures concatenate `m:t` in document order (same rules as docspine). The text flows into `to_text` / `to_markdown`; the PDF draws it as plain text with a one-time `math-text` warning. Iterative walker, deep nesting is safe.
- Fuzzing: standalone cargo-fuzz package (`fuzz/`) with `parse_pptx` / `parse_slide_xml` / `render_pdf` targets, in-code seed generator, and a daily `fuzz.yml` workflow (nightly toolchain, not part of `ci.yml`). No crashes found in initial local runs.

### Changed

- **Breaking (Rust API only):** several public structs gained fields, so struct literals without `..Default::default()` / `..ZipLimits::default()` no longer compile, and two enums gained variants (exhaustive `match` breaks unless the enum is `#[non_exhaustive]`). Checked against `git diff main..HEAD` of `crates/ppt-core/src` and `zip_pkg.rs`. New fields: `Presentation` (`first_slide_num`, `diagnostics`), `Slide` (`comments`), `GroupShape` (`fill`), `Table` (`flags`), `Cell` (`no_fill`), `CellBorders` (`no_left` / `no_right` / `no_top` / `no_bottom`), `Stroke` (`no_fill`), `AutoShape` and `Connector` (`cust_geom`), `GraphicPlaceholder` (`diagram_rel_id`, `diagram_text`), `Chart` (`bar_dir`, `grouping`, `three_d`, `combo`, `of_pie`), `ChartSeries` (`color`, `point_colors`, `labels`), `ResolvedSlide` (`accents`), `ResolvedAutoShape` (`blip_fill`, `blip_from_group`, `cust_geom`), `ResolvedConnector` (`no_line`, `cust_geom`), `ResolvedTable` (`style_resolved`), `ResolvedRun` (`link`), `ZipLimits` (`max_slides`, `max_diagram_shapes`, `max_diagram_text_bytes`, `max_chart_points`, `max_comments`). New variants: `Fill::Pattern { .. }` / `Fill::Group` and `Fill::Blip` became the tuple variant `Fill::Blip(BlipFill)`; `RunKind::Math`; `ResolvedFill::Pattern`; `LimitKind::Slides` and `DiagnosticKind::*` are `#[non_exhaustive]`. `ChartSeries.point_colors` is now sorted by index and unique (first `c:dPt` wins). `ppt_ocr::reconstruct_table_from_image` changed signature (see Added).
- **Python API: new keys, no removed ones.** Callers that compare whole dicts for equality are affected: chart series dicts gain `color` / `point_colors` / `labels`; chart dicts gain `bar_dir` / `grouping` / `three_d` / `combo` / `of_pie`; placeholder shape dicts gain `text` (SmartArt data text); text runs can now have `kind == "math"`; new `Slide.comments()` and `Presentation.diagnostics()`; new `reconstruct_image_table()`; `open` / `open_bytes` take the keyword-only limits. Values that changed: a shape dict `fill` for a pattern fill is now the foreground (else background) color instead of `None`. Callers that read individual keys are unaffected.
- **Behavior change:** `mc:AlternateContent` now prefers `mc:Choice` over `mc:Fallback` (the first Choice that yields substantive content; Fallback only when every Choice is empty). A deck whose Choice and Fallback both hold recognized shapes now renders — and `to_text` / `to_markdown` / `Slide.text` print — the Choice (newer representation) instead of the Fallback, so text output for such decks changes. A Choice holding only a group without any substantive descendant (e.g. grouped ink, whose children are all unrecognized `p14:` elements, at any nesting depth) counts as empty and yields to the Fallback text, like the bare-OLE-placeholder rule (one recursive predicate for both).
- Hidden slides (`show="0"`) are skipped by `to_text`/`to_markdown`/`to_pdf`/`save_pdf` by default (`include_hidden=True` to keep them), matching PowerPoint's PDF export. Text export order defaults to visual reading order. Markdown list indent is now `level × 2` spaces.
- `a:custGeom` shapes whose color comes only from `p:style` are now drawn too (previously nothing was painted). The old bounding-box rectangle (connectors: a straight line) with a `custom-geometry-approximated` warning is now only the fallback for an over-budget or unevaluable `custGeom` (see Added for the real-outline drawing).
- Python export warnings of the `Custom` kind now surface once per kind (previously collapsed into one).
- Align PDF export dependencies with pdfspine v0.8.0 (2026-09-10, `91e0255`;
  previously unrecorded): `pdf-typeset` / `pdf-fonts` git deps and the
  validation notes in `docs/pdfspine-v080-validation.md`.
- Align git deps to ocrspine `041958a` (fixes a reading-order sort panic) and
  pdfspine v0.11.2 (`78a64d6`, pdf-typeset / pdf-fonts); the test extra now
  accepts `pdfspine>=0.8,<0.12`. No behavior change; the 18 SSIM
  self-reference pages are unchanged.

- The `test` extra now accepts `pdfspine>=0.8,<0.13` (validated against pdfspine 0.12.0: 100 pytest passed / 1 skipped, SSIM 18/18). Test-time Python constraint only; the `pdf-typeset` git rev in `Cargo.toml` is unchanged.
- **Behavior change — formula linearization (`a14:m`).** The old rule parenthesized an operand by the *number of `m:t` fragments*, ignoring content, which changed meaning: a single-run numerator `a+b` over `c` came out `a+b/c`, a single-run exponent `n+1` came out `x^n+1`, `m:d` delimiters (characters live in `m:dPr > m:begChr` / `m:endChr` / `m:sepChr`) were dropped (`2(x+1)` → `2x+1`), `m:nary` lost its operator (`m:naryPr > m:chr`, default `∫`) and glued the limits (`i=1nx_i`), and `m:sSubSup` became `xi2`. Now an operand is parenthesized iff its *linearized result* is not an atom (non-empty alphanumeric / decimal-point string incl. Unicode letters, or a string fully wrapped by one matching bracket pair — `(a)+(b)` is not); empty slots print nothing. Output: `(a+b)/c`, `x^(n+1)`, `2(x+1)`, `∑_(i=1)^n x_i`, `x_i^2`; new structures — `m:d` (`[x]`, `(a|b)`), `m:nary`, `m:sSubSup`, `m:sPre` (`_1^2 X`), `m:limLow` / `m:limUpp` (`lim_(n→∞)`), `m:func` (`sin x`, `sin(x+1)`), `m:bar` (`¯`) / `m:acc`, `m:m` (`[a, b; c, d]`), `m:eqArr` (`x=1; y=2`), and transparent `m:box` / `m:borderBox` / `m:groupChr` / `m:phant`. Unknown structures still concatenate `m:t` in document order but now put a space between adjacent child structures (`1 2`, not `12`). Still an iterative walker bounded by the 64-level limit (`nesting-too-deep` unchanged). Callers that stored the old formula text will see different strings for the cases above.

### Fixed

- Text exports: slide-number fields (`a:fld type="slidenum"`) inside **table cells** now print the evaluated page number in `to_text` / `to_markdown` (plain, GFM and HTML table forms), like body shapes; previously the cell echoed the stale cached text because the table export never consulted the resolved cells.
- Slide / layout / master background `p:bgPr > a:pattFill` was silently ignored (no background at all); it now degrades like a shape pattern fill — the mean of `a:fgClr` / `a:bgClr` as a flat full-page color plus a `pattern-fill-degraded` warning (shared warning function). Background `a:blipFill` was already drawn as a full-page picture and is unchanged (now covered by a test).
- Formula (`a14:m`) structures nested deeper than the 64-level limit still degrade to plain concatenation (text is kept), but the degrade is now recorded as a `nesting-too-deep` parse diagnostic (count = degraded subtrees) instead of being silent.
- The presentation main part is no longer hard-coded to `ppt/presentation.xml`: it is located through the `officeDocument` relationship in the package-root `_rels/.rels` (a missing / malformed `.rels`, no such relationship, or a target that is not a part falls back to `ppt/presentation.xml`, i.e. unchanged behavior). The main part's `.rels`, slide order, section ids, comment authors / table styles lookups and the sibling `slides/` `slideLayouts/` `slideMasters/` `theme/` `media/` directories are all derived from the main part's real location (`custom/main.xml` → `custom/slides/…`). Relationship targets resolve against the source part's directory (`links::resolve_part_path`, already used for charts / SmartArt / comments) and a target whose `..` climbs above the package root is rejected instead of being clamped onto the root (a package-root decoy can no longer be reached through an over-long `../`).
- Expanded-form leaf elements (`<a:off x=".." y=".."></a:off>` instead of self-closing) made `parse_xfrm` return at the first child end tag, desynchronizing the parent `spPr` / `grpSpPr` walk: everything after `a:xfrm` (fill, outline, geometry) was lost. `parse_xfrm` now counts depth. A self-closing `<a:p/>` inside a `txBody` was dropped while `<a:p></a:p>` yielded an empty paragraph; both now yield one empty paragraph. A self-closed vs expanded comparison over the other leaf readers (ln / prstDash / headEnd / tailEnd, gradFill, nv / style, bodyPr / lstStyle / pPr / rPr, tcPr edges, gridCol, blipFill, chOff / chExt, bg / clrMapOvr) found no further differences.
- Repeated references no longer amplify work: a slide part listed several times in `p:sldIdLst` is parsed and stored once (first occurrence wins, order kept), and a chart part referenced by many `graphicFrame`s is parsed once (cached by part path; the cache only saves parsing — every frame still receives its own copy, so memory is bounded by the expansion budgets listed under Security, not by the cache). New `ZipLimits.max_slides` (default 5 000, counted after de-duplication) returns `PptError::LimitExceeded { kind: LimitKind::Slides, .. }` when exceeded. Breaking for Rust callers: `ZipLimits` gains a field (struct-literal construction without `..ZipLimits::default()`) and `LimitKind` gains `Slides` (already `#[non_exhaustive]`).
- `mc:AlternateContent` no longer loses content: both at shape-tree level and inside `a:p`, the first `mc:Choice` (document order) that yields content is used and `mc:Fallback` is taken only when every Choice is empty (e.g. an unknown `p14:` / `a14:` element) — never both, so nothing is duplicated. Previously every Choice was skipped, so content with no Fallback vanished, and paragraph-level AlternateContent / `a14:m` formulas were dropped.
- Explicit "no outline" shapes (`a:spPr > a:ln > a:noFill`, with or without `@w`) were parsed as a width-only stroke and drawn as a default black line (connectors: the "no stroke → black" fallback); `parse_ln` now returns `Stroke.no_fill`, so the outline is not drawn and wins over the `lnRef` theme line (`ResolvedConnector.no_line`). Shapes without `a:ln` still inherit `lnRef`. Pictures and text runs do not model `a:ln`, so are unaffected.
- Explicit "no border" cell edges (`a:lnL/lnR/lnT/lnB > a:noFill`, with or without `@w`) were parsed as a width-only stroke and drawn as a default black line, overriding the table style's edge; they now hide that edge (`CellBorders.no_left/no_right/no_top/no_bottom`) and win over the table style as explicit properties.
- CI wheels job "Wheel OCR smoke" had failed since 2026-07 (the `--no-index`
  install could not resolve the hard dependency `ocrspine-models`); it now
  installs the models package first, then the locally built wheel with
  `--no-index`. The pytest job installs `.[test]` and runs with `-ra`.
- `ppt-ocr` isolates panics from the ocrspine engine, image decode and engine
  construction into `PptError::Ocr` (Python `PptOcrError`) instead of letting
  them escape as `PanicException`; words with NaN/Inf bbox or confidence are
  dropped.

### Security

- Parse-time shape / content budgets. Before this, one part's memory was bounded only by the 256 MiB per-entry limit: a 7-byte empty `<a:p/>` or a 19-byte `<p:cxnSp></p:cxnSp>` becomes a 384-byte / 560-byte model object, so a small part could inflate to tens of GB. New `ZipLimits` fields `max_part_shapes` (20 000) / `max_total_shapes` (200 000) bound shape elements parsed per part / across the whole deck (slides, layouts, masters and SmartArt drawings, each part once; ~200 MB at worst) and `max_part_items` (200 000) / `max_total_items` (1 000 000) bound text and table nodes (paragraphs, runs, table rows / cells / grid columns, gradient stops, colour transforms, shape adjust values, theme style lists, notes paragraphs; ~400 MB at worst). At the limit the part stops growing early — what was parsed is kept, the rest is only scanned past — and new diagnostics `shapes-truncated` / `content-truncated` (`DiagnosticKind::ShapesTruncated` / `ContentTruncated`, count = dropped elements) are recorded. They govern *parsing* and are independent of `max_diagram_shapes`, which governs *expansion* (copies per SmartArt frame); both apply. Python: `open` / `open_bytes` take the four new keyword-only arguments (stub updated). Known gap: the `p:sldId` list of `presentation.xml` is still only capped by `max_slides` after it has been read. Breaking for Rust callers: `ZipLimits` struct literals need the four new fields (or `..ZipLimits::default()`), `DiagnosticKind` is `#[non_exhaustive]` so `match` already needs a wildcard; `ppt_parse` internals only otherwise.
- The zip reader no longer pre-allocates from the entry's declared size, and
  reads are capped. New `ZipLimits` (defaults: 10 000 entries, 256 MiB per
  entry, 1 GiB total, compression ratio 10 000 for entries > 1 MiB, 1024-byte
  names) -> `PptError::LimitExceeded` (Python `PptZipError`). Absolute, drive-letter and `..`
  entry paths are rejected. Group-shape / `mc:AlternateContent` nesting deeper
  than 64 is skipped to avoid stack overflow. New `parse_bytes_with_limits` /
  `parse_path_with_limits`.
- Amplification fixes from an independent review of this series (tiny synthetic files that fanned out into minutes of CPU or GB of memory):
  - Expansion budgets, cumulative over the whole deck (every frame that re-uses a SmartArt / chart part is charged again): `ZipLimits.max_diagram_shapes` (100 000), `max_diagram_text_bytes` (8 MiB), `max_chart_points` (1 000 000). A frame that would exceed one is degraded to a placeholder box with a `smartart-degraded` / `chart-degraded` diagnostic. A single SmartArt drawing part is also capped at 10 000 shapes. Caching the parse does not bound the clones, which is why the budgets exist.
  - Comments: a comments part referenced several times by one slide is read once (new diagnostic `duplicate-comment-ref`), parses are cached across slides, and the deck-wide comment count including replies is capped by `ZipLimits.max_comments` (100 000; the parser stops at the cap; new diagnostic `comments-truncated`).
  - Diagnostics: collection is indexed by `(kind, part)` (was a linear scan), distinct entries are capped at 10 000 (overflow merges into one summary entry per kind with `part == ""`, counts still add up), and `part` is only ever a real package part path (<= 1024 bytes) — a relationship pointing at a missing part is attributed to the part holding the relationship, never to the target string written in the file. Nesting overflow inside comment bodies and SmartArt data parts is now recorded too (it used to be reset by the next `parse_part`).
  - Pie charts: the point / category limit is checked before any size-dependent work and the legend is capped at 64 entries (the legend used to rescan the whole series per category: ~55 s for a 256 000-point pie declared by `ptCount` alone). Per-point colors are looked up by binary search.
  - Shape fill `a:grpFill` inheriting a picture fill still stretches the picture per child rectangle (PowerPoint lays it over the group extent); it now emits a `group-blip-fill-stretched` export warning (`ResolvedAutoShape.blip_from_group`).
  - Chart `c:dPt` with a repeated `idx`: the first one in document order wins everywhere (renderer and Python `point_colors` used to disagree).
- Byte-level amplification is now one budgeted class instead of per-shape fixes (second review round; the old budgets counted *items* while memory grows with *bytes × copies*):
  - **Model byte budget** `ZipLimits.max_model_bytes` (Python `max_model_bytes=`): every non-shared node is charged its struct size and every string its actual bytes as it is produced (`attr_string` / `read_text` charge centrally), across slides, layouts, masters, themes, table styles, notes, comments, SmartArt data / drawings and charts; per-frame / per-slide copies (SmartArt clones, comment copies) are charged per copy. Exhaustion stops early with `content-truncated` / `value-truncated` / `chart-degraded` / `smartart-degraded`. `ppt_parse::estimated_model_bytes` / `ppt_core::model_bytes` give the same estimate to callers; the property "estimate ≤ budget, diagnostic when exceeded" is tested per amplification family (`crates/ppt-parse/tests/byte_budget.rs`). Item / shape counts stay as a second gate.
  - **Shared instead of cloned:** comment author / initials and hyperlink targets are `Arc<str>` (one copy per author / relationship), parsed charts are `Arc<Chart>` shared by every frame (charged once), resolved charts with identical terminal colors are shared too, `ResolvedRun.link` shares the model string. Python converts each shared value to one `str` object per call (no fan-out at the boundary).
  - **Single-value caps** with the new `value-truncated` diagnostic: attribute values 64 KiB, text nodes 1 MiB (streamed, not read whole first), comment author / chart category / series / title labels 4 KiB, hyperlink targets 16 KiB, OMML `m:chr` / `begChr` / `endChr` / `sepChr` 2 characters (a long separator was joined once per `m:e`).
  - **Comments:** parts are parsed only up to the *remaining* budget (`min(max, left)`) and skipped entirely once it is 0 (each part used to be parsed up to the global maximum even after the budget was spent); replies count.
  - **`p:sldIdLst`** is deduplicated while reading and collection stops after `max_slides + 1` distinct slides (the list used to be fully materialized first); section id lists are capped at `max_slides`.
  - **Rendering:** `RenderOptions.max_page_ops` / `max_total_ops` (Python `to_pdf(max_page_ops=, max_total_ops=)`) bound the op weight per page / per document (groups and tables stop at child / cell granularity, keeping the drawn prefix; `render-budget` warning). Master / layout shapes materialized per slide by `resolve` are capped at `MAX_INHERITED_SHAPES` instances (`ResolvedPresentation.inherited_dropped`, `inherited-shapes-truncated` warning). Form XObject reuse was evaluated: pdf-typeset at the pinned rev has no form XObjects, so only budgets.
  - **Exports:** `ExportOptions.max_output_bytes` (default 64 MiB; Python `to_text(max_output_bytes=)` / `to_markdown(...)`) stops generating at the cap, truncates on a char boundary and appends a `[pptspine: output truncated at N bytes]` line (`presentation_text_bounded` / `presentation_markdown_bounded` return `truncated`; Python warns).
  - **Defaults no longer truncate large legitimate decks; truncation is fair and reported truthfully.** A 500-page deck with a 50×20 table per page (596 KB) used to exceed `max_total_items` (1 000 000): pages 326–500 came out with no text at all while diagnostics reported 12 401 dropped items for ~530 000 actually lost nodes. New count defaults are ≥ 4× the measured needs of a benchmark set that is now a regression test (`tests/legit_benchmarks.rs`, zero truncation / zero diagnostics under defaults): `max_total_items` 8 000 000 (500 × 50×20 tables need 1 536 000), `max_total_shapes` 1 000 000 (2 000 pages × 100 shapes need 200 000), `max_chart_points` 2 000 000 (100 pages × 20 charts need 500 000), `max_model_bytes` 2 GiB (the table deck needs 0.76 GB). Fairness: layouts / masters / themes / table styles are parsed before slides, every slide's own parts (charts, SmartArt, notes, comments) right after it, and before any part is parsed the remaining slides' floors (`min(2 000 items / 100 shapes / 2 MiB, left / slides)`) are reserved — an exhausted deck loses each page's tail instead of its second half. `shapes-truncated` / `content-truncated` counts now include every descendant of a skipped container (rows, cells, paragraphs, runs, grouped shapes). New `Presentation.report: ParseReport` (`truncated()`, `truncated_parts` — every part with content loss, not subject to the 10 000-entry diagnostic cap — `dropped_shapes` / `dropped_items` / `truncated_values`, `shapes_used` / `items_used` / `model_bytes`); Python `Presentation.truncated` and `Presentation.parse_report()`. Notes, themes, table styles, comments and SmartArt data no longer use a private default budget: they obey the caller's limits, count against the deck totals and report truncation (`content-truncated`).
  - **Breaking (Rust API):** `Comment.author` / `initials`, `Hyperlink.url`, `ResolvedRun.link` are `Option<Arc<str>>`; `GraphicPlaceholder.chart` is `Option<Arc<Chart>>`; new fields `Presentation.report`, `ZipLimits.max_model_bytes`, `ExportOptions.max_output_bytes`, `RenderOptions.max_page_ops` / `max_total_ops` (`RenderOptions` / `ExportOptions` no longer derive `Default`; they implement it), `ResolvedPresentation.inherited_dropped`; new `DiagnosticKind::ValueTruncated`.

## [0.4.0] — 2026-07-13

### Added

- **Recompute autofit for text boxes (B-6).** When `a:normAutofit` is on but no
  `fontScale` was stored, the exported text now shrinks to fit its box: driven by
  the engine's TS-10 `measure_text_box`, it steps `fontScale` down (95%→25%) and
  escalates `lnSpcReduction` (0→10→20%), taking the first combination whose
  measured content height fits — the scale is baked into the runs so the engine
  does not re-shrink. A **stored** `normAutofit@fontScale` keeps its
  applied-as-stored behavior (no regression).
- **Content-adaptive table row height (B-7).** Each row now grows to
  `max(declared/frame-derived height, measured content height)` via TS-10
  `measure_blocks`, so long cell text is no longer clipped; `rowSpan` cells
  distribute their content height evenly across the rows they span. Rows whose
  content fits render byte-identically to before (no unintended drift).
- Bumped the pinned `pdf-typeset` / `pdf-fonts` engine rev to pdfspine v0.3.1
  (`5f1640c`), which adds the public TS-10 measurement API both features consume.

- **Self-render SSIM regression gate (B-11 gate (4)).** Committed grayscale
  references (`python/tests/ssim_refs/*.ssimref`) captured from our own
  `to_pdf()` output on a pinned-font runner; CI re-renders the full synthetic
  fixture matrix, rasterises through pdfspine and asserts per-page
  SSIM ≥ 0.97 (plus size-match and no near-blank regression). Unlike the
  LibreOffice oracle (advisory, never-CI), this is a **CI-blocking** gate that
  turns any unintended render drift into a red build. Regenerate deliberately
  after an intended render change with
  `python scripts/ssim_baseline.py --make-references`. The pytest gate is
  font-runner-sensitive, so it enforces on ubuntu / py3.12 only (gated by
  `PPTSPINE_SSIM_GATE`); the rest of the matrix skips it. CI now installs
  `pdfspine>=0.3` for the read-back gates.
